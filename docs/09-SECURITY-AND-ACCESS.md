## مدل مجوز

RBAC برای نقش کلی و کنترل رابطه/منبع برای هر عملیات استفاده شود. «داوطلب بودن» مجوز دیدن مکان دقیق تمام گربه‌ها نیست. policy باید actor، resource، action، عضویت/assignment فعال و حساسیت داده را بررسی کند. deny پیش‌فرض است.

## کنترل‌های لازم

- session امن با cookie مناسب HttpOnly/Secure/SameSite و کنترل CSRF/Origin برای mutationهای cookie-based.
- OTP hash‌شده، expiry، محدودیت attempt و عدم افشای وجود حساب؛ logout و revoke session.
- rate limiting اشتراکی بین instanceها برای OTP، گزارش، پیام، upload و checkout.
- اعتبارسنجی schema سمت سرور، SQL پارامتری و output encoding؛ HTML دلخواه در پست پذیرفته نشود.
- فایل قرنطینه، بررسی magic bytes، حجم/ابعاد، پاکسازی EXIF و signed URL کوتاه‌عمر.
- نام کاربری، جست‌وجو و URL با نرمال‌سازی کنترل‌شده؛ فایل کاربر مسیر filesystem تعیین نکند.
- webhook با امضا و replay protection؛ کلیدهای provider در secret manager یا env سرور.
- هیچ NEXT_PUBLIC حاوی secret نباشد. `.env.example` فقط نام متغیر دارد.
- لاگ فاقد OTP، token، شرح پزشکی، محتوای مشاوره و مکان دقیق باشد.
- grant دقیق زمان‌دار، audit خواندن حساس و invalidate مجوز پس از لغو نقش.
- نسخهٔ عمومی فایل و DTO از نسخهٔ اصلی جدا؛ CSS hide حفاظت داده نیست.

## حریم خصوصی مکان

سلول عمومی ثابت و قابل بزرگ‌تر شدن برای محل حساس. زمان دقیق و مسیر متوالی مراقب عمومی نشود. درخواست‌های مکرر، فاصلهٔ عددی دقیق و sort بر اساس فاصلهٔ خصوصی نباید مکان اصلی را بازسازی کنند. مختصات عکس و تصویر نقشهٔ خصوصی در thumbnail عمومی باقی نماند.

## نگهداری و حذف

درخواست دریافت/حذف داده در محصول ثبت و وضعیت پاسخ مشخص شود. مدت نگهداری مالی، پزشکی، پیام و consent در D13 تعیین می‌شود. تا تعیین سیاست، در staging فقط دادهٔ ساختگی استفاده شود. deletion برای محتوای عمومی و anonymization برای رکوردهایی که باید طبق سیاست حفظ شوند جداست. backup نیز سیاست انقضا دارد.

## تعدیل محتوا

گزارش آزار، انتشار اطلاعات شخصی، جعل حرفه، درخواست مالی مشکوک و رسانهٔ نامناسب به queue ناظر می‌رود. تصمیم همراه دلیل و امکان اعتراض ثبت شود. لیست عمومی متهمان به حیوان‌آزاری ساخته نشود. مسیر مشاوره از گزارش تخلف مستقل است و اطلاعات فرد گزارش‌شده خودکار به مشاور ارسال نشود.

## رخداد امنیتی

تشخیص → محدودکردن دسترسی/کلید آسیب‌دیده → حفظ شواهد بدون تکثیر دادهٔ حساس → رفع و بازیابی → اطلاع‌رسانی بر اساس سیاست مصوب → ثبت علت و آزمون جلوگیری از تکرار. مسئول on-call و مسیر تماس باید قبل انتشار مشخص باشد.

این سند طراحی امنیت است. ادعای انجام ممیزی مستقل یا تأیید امنیت محصول نیست.
