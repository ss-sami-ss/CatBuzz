# طراحی حرکت (Motion Design)

نسخهٔ 1.0 — 2026-11-15 — مصوب کارفرما در D20. این سند مرجع همهٔ انیمیشن‌های CatBuzz است. مقادیر از اسکیل‌های `emil-design-eng` و `animate` گرفته شده‌اند و قواعد کارایی از `vercel-react-best-practices`. اجرای واقعی در T04 و تسک‌های UI انجام و با دستگاه واقعی بازبینی می‌شود. هنوز کدی ساخته یا تست نشده است.

## شعار و معنای عملی

**سریع، معنادار، صیقل‌خورده.**

- **سریع:** انیمیشن UI زیر 300ms است. استثناها (sheet، drawer، modal و toast) در جدول توکن‌ها آمده‌اند. خروج همیشه از ورود سریع‌تر است.
- **معنادار:** هر انیمیشن یکی از این هدف‌ها را دارد: بازخورد، پیوستگی مکانی، نمایش تغییر وضعیت یا جلوگیری از پرش ناگهانی. «قشنگ است» دلیل کافی نیست.
- **صیقل‌خورده:** فقط `transform` و `opacity` (و `clip-path` در موارد خاص) انیمیت می‌شوند. curveها سفارشی‌اند، هیچ چیز از `scale(0)` ظاهر نمی‌شود و حرکت قابل قطع است.
- **بازیگوشی:** فقط در لحظه‌های نادر و پرمعنا، مثل پایان موفق مأموریت، سپردن گربه به سرپرست دائم یا اولین گزارش کاربر. بخش «لحظه‌های بازیگوش» را ببینید.

## دروازهٔ تصمیم: انیمیشن داشته باشد یا نه؟

پیش از ساختن هر انیمیشن، این دو سؤال به ترتیب پاسخ داده می‌شوند (`emil-design-eng`). اگر پاسخ منفی بود، کدی نوشته نمی‌شود و این یک نتیجهٔ درست است.

| دفعات دیدن | تصمیم | نمونه در CatBuzz |
|---|---|---|
| صدها بار در روز یا با صفحه‌کلید | **بدون انیمیشن** | میان‌برهای صفحه‌کلید، بستن با Escape، جابه‌جایی focus، تایپ در جست‌وجو |
| ده‌ها بار در روز | بسیار کوتاه یا هیچ | hover کارت، انتخاب chip فیلتر، تب‌های نوار پایین، انتخاب marker |
| گاه‌به‌گاه | انیمیشن استاندارد | bottom sheet، Drawer، Dialog، toast، جابه‌جایی صفحه، ظاهر شدن نتایج |
| نادر یا بار اول | مجاز به بازیگوشی | پایان مأموریت، تحویل گربه، اولین ثبت گزارش، تأیید پروفایل نگهدارنده |

داده‌ای که کاربر می‌خواند یا بر اساس آن تصمیم می‌گیرد برای زیبایی حرکت نمی‌کند. مبلغ، فاکتور، وضعیت فوری و نقشه را count-up یا تکان نمی‌دهیم.

## Motion tokens

توکن‌ها یک بار به شکل CSS custom property روی `:root` تعریف می‌شوند. springها چون در CSS قابل بیان نیستند، به شکل ثابت TypeScript در `src/shared/motion/` می‌آیند. مقدار خارج از این جدول hard-code نمی‌شود. اگر مقدار تازه‌ای لازم شد، اول به همین سند اضافه می‌شود.

### مدت‌زمان

| Token | مقدار | کاربرد |
|---|---|---|
| `--duration-instant` | 0ms | کارهای صفحه‌کلید، حالت reduced motion برای حرکت مکانی |
| `--duration-press` | 140ms | بازخورد فشردن دکمه و کارت |
| `--duration-fast` | 160ms | tooltip، popover کوچک، تغییر رنگ، خروج صفحه |
| `--duration-base` | 220ms | dropdown، select، ورود صفحه، تب |
| `--duration-modal-in` | 250ms | ورود Dialog در دسکتاپ |
| `--duration-modal-out` | 200ms | خروج Dialog |
| `--duration-item` | 260ms | ورود هر کارت در stagger |
| `--duration-drawer-in` | 450ms | باز شدن Drawer بدون کشیدن |
| `--duration-drawer-out` | 300ms | بسته شدن Drawer بدون کشیدن |
| `--duration-toast` | 400ms | toast (با `ease`، طبق الگوی Sonner) |
| `--stagger-step` | 0، 40، 75، 105، 130، 150ms | تأخیر کارت‌های 1 تا 6 (فاصلهٔ کاهشی، نه یکنواخت) |

### Easing

| Token | مقدار | کاربرد |
|---|---|---|
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | ورود و خروج؛ پیش‌فرض |
| `--ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | حرکت روی صفحه، مثل نشانگر تب |
| `--ease-drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | Drawer و sheet بدون کشیدن |
| `ease` | استاندارد CSS | hover، تغییر رنگ، toast |
| `linear` | استاندارد CSS | progress، نگه‌داشتن برای تأیید |

`ease-in` در UI ممنوع است. شروع کندش دقیقاً لحظه‌ای را عقب می‌اندازد که کاربر نگاه می‌کند.

### Spring

از قالب Apple (duration و bounce) استفاده می‌کنیم، چون فهمیدنش ساده‌تر است.

| Token (TS) | مقدار | کاربرد |
|---|---|---|
| `spring.snap` | `{ type: "spring", duration: 0.4, bounce: 0 }` | رسیدن sheet یا Drawer به حالت بعدی پس از رها کردن |
| `spring.release` | `{ type: "spring", duration: 0.45, bounce: 0.15 }` | رها کردن با سرعت زیاد (flick) و drag-to-dismiss |
| `spring.playful` | `{ type: "spring", duration: 0.5, bounce: 0.3 }` | فقط لحظه‌های بازیگوش |

bounce در UI معمولی صفر است. 0.15 فقط برای حرکت ناشی از انگشت است و 0.3 فقط برای لحظه‌های نادر.

## قواعد کلی

1. **ویژگی‌ها:** فقط `transform` و `opacity` انیمیت می‌شوند. `clip-path` برای reveal مجاز است. انیمیت کردن `height` فقط برای accordion کوتاه پذیرفته است. `width`، `margin`، `padding`، `top` و `left` ممنوع‌اند.
2. **ورود:** هیچ چیز از `scale(0)` ظاهر نمی‌شود. شروع از `scale(0.96)` و `opacity: 0` است.
3. **مبدأ:** popover، dropdown و tooltip از سمت trigger باز می‌شوند (`transform-origin` روی محل trigger). Dialog مرکزی از مرکز باز می‌شود.
4. **قطع‌پذیری:** برای چیزی که سریع تکرار می‌شود (toast، toggle) از transition استفاده می‌شود، نه keyframes. برای gesture از spring، تا سرعت در قطع شدن حفظ شود.
5. **مسیر خروج:** خروج از همان مسیری است که ورود از آن بود. toastی که از پایین آمده از پایین می‌رود.
6. **فشردن:** هر عنصر قابل فشردن هنگام `:active` به `scale(0.97)` با `--duration-press` و `--ease-out` می‌رود.
7. **hover:** فقط داخل `@media (hover: hover) and (pointer: fine)`، چون لمس hover کاذب می‌سازد.
8. **reduced motion:** با `prefers-reduced-motion: reduce` حرکت مکانی حذف می‌شود، ولی fade کوتاه (`--duration-fast`) که فهم را آسان می‌کند می‌ماند. reduced motion یعنی کمتر و ملایم‌تر، نه صفر. این قاعده همراه خود انیمیشن ساخته می‌شود، نه بعداً.
9. **قفل نکردن:** انیمیشن هیچ‌وقت تعامل را مسدود نمی‌کند. کاربر در حین stagger یا transition می‌تواند کلیک کند.
10. **حلقهٔ بی‌پایان:** pulse یا shimmer دائمی ممنوع است، حتی روی وضعیت فوری. skeleton بارگذاری تنها استثناست و با reduced motion ثابت می‌شود.
11. **ابزار:** ارزان‌ترین ابزاری که کار می‌کند انتخاب می‌شود: CSS transition، سپس `@starting-style`، سپس CSS animation، سپس WAAPI و در آخر کتابخانهٔ Motion فقط برای spring، gesture و exit.

## جهت حرکت در RTL

CatBuzz راست‌به‌چپ است. جهت‌ها با «آغاز» (inline-start، در RTL سمت راست) و «پایان» (inline-end، در RTL سمت چپ) تعریف می‌شوند، نه با چپ و راست.

| حرکت | جهت در RTL | توضیح |
|---|---|---|
| رفتن به صفحهٔ عمیق‌تر | صفحهٔ جدید از پایان (چپ) وارد می‌شود و صفحهٔ قبلی کمی به آغاز (راست) می‌رود | قرینهٔ push در LTR |
| بازگشت | صفحهٔ فعلی به پایان (چپ) می‌رود و صفحهٔ قبلی از آغاز (راست) برمی‌گردد | |
| Drawer ناوبری | از آغاز (راست)، همان سمت sidebar دسکتاپ | |
| Drawer فیلتر و جزئیات | از پایان (چپ) | |
| bottom sheet و toast | عمودی؛ تحت تأثیر RTL نیست | |
| swipe برای بستن toast یا کارت | به سمت پایان (چپ) | |
| progress و نوار تأمین مالی | از راست به چپ پر می‌شود | |
| نشانگر تب | در محور افقی با ترتیب RTL تب‌ها جابه‌جا می‌شود | |
| آیکون‌های جهت‌دار (بازگشت، chevron) | قرینه می‌شوند | آیکون‌های غیرجهت‌دار مثل پنجه و تیک قرینه نمی‌شوند |

در پیاده‌سازی، `--dir` روی `:root` یک بار تعریف می‌شود: `1` برای LTR و `-1` برای `[dir="rtl"]`. جابه‌جایی «از پایان» با `translateX(calc(100% * var(--dir)))` نوشته می‌شود. چون `--dir` ثابت است، هزینه‌ای ندارد. ولی متغیر CSS هرگز در حین انیمیشن یا drag روی والد تغییر نمی‌کند، چون style همهٔ فرزندان را دوباره محاسبه می‌کند. مقدار drag مستقیم روی `transform` همان عنصر نوشته می‌شود.

## جاهایی که انیمیشن دارند

### ۱. جابه‌جایی بین صفحه‌ها

دفعات: گاه‌به‌گاه تا ده‌ها بار در روز. هدف: پیوستگی مکانی (کجا رفتم، از کجا برگشتم).

- **ناوبری سلسله‌مراتبی** (فهرست به پرونده، پرونده به گزارش): صفحهٔ جدید با `opacity` 0 به 1 و جابه‌جایی 24px از پایان در `--duration-base` و `--ease-out` وارد می‌شود. صفحهٔ قبلی در `--duration-fast` محو می‌شود. جابه‌جایی کامل 100% استفاده نمی‌شود، چون برای ده‌ها بار در روز سنگین است.
- **ناوبری هم‌سطح** (تب‌های نوار پایین و آیتم‌های sidebar): بدون جابه‌جایی، فقط crossfade در `--duration-fast`. با کلیک صفحه‌کلید هیچ انیمیشنی اجرا نمی‌شود.
- **نقشه:** خود نقشه هرگز در transition صفحه حرکت نمی‌کند و state آن (مرکز، zoom، انتخاب) حفظ می‌شود.
- **بازگشت با gesture مرورگر:** وقتی مرورگر خودش انیمیشن بازگشت دارد (swipe در iOS Safari)، transition ما اجرا نمی‌شود تا دو انیمیشن روی هم نیفتند.
- **ابزار:** View Transitions API (CSS، روی compositor). پشتیبانی React/Next.js از `ViewTransition` در T02 از مستندات رسمی نسخهٔ قفل‌شده بررسی می‌شود. اگر پایدار نبود، برای مرورگرهای فاقد پشتیبانی جابه‌جایی بدون انیمیشن انجام می‌شود، نه با کتابخانهٔ JS سنگین.
- **reduced motion:** فقط crossfade در `--duration-fast`.

### ۲. bottom sheet، Drawer و Dialog

هدف: پیوستگی مکانی و قابلیت کشیدن با انگشت. ابزار: Motion (spring و gesture)، که فقط در همین کامپوننت‌ها و با import مستقیم بارگذاری می‌شود.

**bottom sheet موبایل** (صفحهٔ اول، خلاصهٔ گربه، فیلترها):

- **حالت‌ها:** سه حالت بسته، خلاصه و باز، طبق [UX](04-UX-DESIGN.md).
- **باز و بسته با لمس دکمه:** `--duration-drawer-in` و `--ease-drawer`. در حالت بسته `translateY(100%)` است.
- **کشیدن:** sheet دقیقاً همراه انگشت حرکت می‌کند. با رها کردن، حالت مقصد از روی فاصله یا سرعت انتخاب می‌شود: سرعت بیشتر از 0.11px/ms یعنی رفتن به حالت بعدی در جهت حرکت، حتی اگر فاصله کم باشد. حرکت تا مقصد با `spring.snap` و برای flick با `spring.release` است.
- **مرزها:** کشیدن بیش از حالت باز با اصطکاک فزاینده (damping) همراه است و توقف ناگهانی ندارد.
- **pointer capture** از شروع drag فعال می‌شود. انگشت دوم در حین drag نادیده گرفته می‌شود.
- **محتوای قابل اسکرول:** drag sheet فقط وقتی شروع می‌شود که محتوای داخلی در بالاترین نقطه باشد. وگرنه همان اسکرول عادی است.
- **پس‌زمینه:** در حالت خلاصه پس‌زمینه تیره نمی‌شود تا نقشه قابل استفاده بماند. در حالت باز `opacity` پس‌زمینه همراه پیشرفت sheet تغییر می‌کند.
- **دسترس‌پذیری:** دکمهٔ بستن، مدیریت focus و Escape لازم است. Escape بدون انیمیشن یا با `--duration-fast` می‌بندد، چون از صفحه‌کلید آمده است.

**Drawer:** ناوبری از آغاز و فیلتر/جزئیات از پایان (جدول RTL). باز شدن با `--duration-drawer-in` و بسته شدن با `--duration-drawer-out`، هر دو با `--ease-drawer`. کشیدن افقی برای بستن، با همان قواعد سرعت، pointer capture و `spring.release`.

**Dialog:**

- **دسکتاپ:** Dialog مرکزی است و کشیدنی نیست. ورود `scale(0.96)` و `opacity: 0` به حالت عادی در `--duration-modal-in` با `--ease-out` است، از مرکز. خروج در `--duration-modal-out` انجام می‌شود و `opacity` پس‌زمینه هم‌زمان تغییر می‌کند.
- **موبایل (زیر 768px):** Dialog به شکل bottom sheet با drag-to-dismiss نمایش داده می‌شود.
- **پیشنهاد نسبت به درخواست اولیه:** spring و کشیدن برای Dialog مرکزی دسکتاپ پیشنهاد نمی‌شود. modal به trigger وابسته نیست و gesture روی آن معنای مکانی ندارد. حس spring با sheet موبایل تأمین می‌شود.
- **فرم پرشده یا تصمیم حساس** (رضایت مشاوره، تأیید پرداخت، فرم درخواست نگهداری با تغییر ذخیره‌نشده): drag-to-dismiss با مقاومت به جای خود برمی‌گردد و تأیید بستن می‌خواهد تا ورودی کاربر با یک swipe تصادفی از دست نرود.

### ۳. ظاهر شدن پشت‌سرهم کارت‌ها (stagger)

دفعات: گاه‌به‌گاه. هدف: جلوگیری از پرش ناگهانی و نشان دادن «نتیجهٔ تازه».

- **چه زمانی:** فقط در بار اول فهرست و پس از «جست‌وجو در این محدوده» یا تغییر فیلتری که نتیجهٔ تازه می‌آورد. در صفحه‌بندی (آیتم‌های اضافه‌شده در پایین)، بازگشت به صفحه و refetch پس‌زمینه stagger نداریم. آیتم‌های جدید فقط fade در `--duration-fast` دارند.
- **حرکت:** هر کارت با `opacity` 0 به 1 و `translateY(8px)` به 0 در `--duration-item` و `--ease-out` وارد می‌شود. تأخیرها `--stagger-step` هستند. فقط 6 کارت اول stagger دارند و بقیه با کارت ششم ظاهر می‌شوند، پس کل ورود کمتر از 450ms طول می‌کشد.
- **ابزار:** CSS animation روی compositor، تا هنگام بارگذاری صفحه روان بماند. بدون JS.
- **از skeleton به محتوا:** skeleton با `--duration-fast` محو می‌شود و stagger از همان لحظه شروع می‌شود، بدون فاصلهٔ خالی.
- **همگامی با نقشه:** انتخاب marker و کارت همگام فقط با تغییر رنگ و حاشیه در `--duration-fast` و `ease` نشان داده می‌شود، بدون حرکت یا اسکرول پرشی.
- **reduced motion:** همهٔ کارت‌ها با یک fade کوتاه و بدون تأخیر ظاهر می‌شوند.

### لحظه‌های بازیگوش

هویت «Buzz» در یک جا خرج می‌شود: آیکون پنجهٔ CatBuzz یک «لرزش» کوتاه دارد (چرخش 8- به 8+ درجه و بازگشت با `spring.playful`). این لرزش فقط یک بار و فقط در این لحظه‌ها اجرا می‌شود:

- پایان موفق مأموریت
- تحویل گربه به سرپرست دائم یا پایان موفق نگهداری
- اولین ثبت گزارش کاربر

این حرکت روی یک `div` دور SVG اعمال می‌شود، نه خود SVG (`rendering-animate-svg-wrapper`). در reduced motion فقط تغییر رنگ پنجه باقی می‌ماند. هیچ confetti یا جشن تمام‌صفحه‌ای نداریم.

## بقیهٔ اجزا (خلاصه)

| جزء | مشخصات |
|---|---|
| Button و کارت قابل فشردن | `:active` به `scale(0.97)`؛ `--duration-press`؛ `--ease-out` |
| Tooltip | `--duration-fast`؛ از trigger؛ پس از اولین tooltip، بقیه بی‌تأخیر و بی‌انیمیشن |
| Dropdown و Select | `scale(0.96)` و opacity؛ `--duration-base`؛ از trigger |
| Toast | از پایین (بالای نوار پایین موبایل)؛ `--duration-toast` با `ease`؛ transition و نه keyframes؛ swipe به پایان؛ تایمر وقتی تب پنهان است متوقف می‌شود |
| Tabs | نشانگر با `--ease-in-out` و `--duration-base` |
| پیام چت تازه | fade در `--duration-fast`؛ بدون slide |
| نقشه، marker و cluster | انیمیشن پیش‌فرض کتابخانهٔ نقشه با zoom؛ انیمیشن اضافهٔ ما ندارد |
| مبلغ، فاکتور، وضعیت فوری | بدون انیمیشن |

## کارایی و پیاده‌سازی (vercel-react-best-practices)

- **CSS اول:** انیمیشن‌های از پیش تعیین‌شده CSS هستند و روی compositor اجرا می‌شوند، تا هنگام بارگذاری صفحه frame نیندازند. Motion فقط برای sheet، Drawer و لحظه‌های بازیگوش است.
- **بارگذاری Motion:** فقط در Client Componentهایی که لازمش دارند، با import مستقیم از مسیر بسته (`bundle-barrel-imports`). sheet و Drawer سنگین با `next/dynamic` و preload روی hover یا focus بارگذاری می‌شوند (`bundle-dynamic-imports`، `bundle-preload`). امکان کاهش bundle با `LazyMotion` در T02 روی نسخهٔ قفل‌شده بررسی می‌شود.
- **re-render:** مقدار drag و پیشرفت sheet در motion value یا ref نگه داشته می‌شود، نه React state، تا هر frame re-render نسازد (`rerender-use-ref-transient-values`). state باز یا بسته بودن sheet در Model بخش MVI است. مقدار لحظه‌ای gesture در Model نیست.
- **listener:** listenerهای touch و scroll از نوع passive هستند (`client-passive-event-listeners`).
- **فهرست بلند:** `content-visibility: auto` برای فهرست‌های بلند (`rendering-content-visibility`). stagger فقط روی 6 کارت اول است.
- **layout animation:** Motion layout animation (`layout` و `layoutId`) روی main thread اجرا می‌شود و هنگام بارگذاری صفحه frame می‌اندازد، پس فقط با دلیل اندازه‌گیری‌شده استفاده می‌شود.
- **hydration:** انیمیشن ورود نباید باعث پرش یا mismatch در hydration شود. محتوای SSR بدون انیمیشن قابل دیدن است.
- **هدف‌ها:** INP ≤ 200ms (N03) با انیمیشن‌ها حفظ شود. اندازه‌گیری روی دستگاه میان‌رده انجام می‌شود.

## آزمون

- **e2e:** Playwright با `reducedMotion: 'reduce'` اجرا می‌شود تا نتیجه پایدار باشد. یک مسیر هم با حرکت کامل برای sheet و Dialog تست می‌شود: focus، Escape، بازگشت focus و نبود اسکرول افقی در 360px (Q28).
- **unit:** منطق انتخاب حالت sheet (فاصله، سرعت، حالت فعلی) تابع خالص است و تست واحد دارد.
- **feel-check دستی** (در گزارش تسک ثبت می‌شود):
  - پخش با سرعت 2 تا 5 برابر کندتر در DevTools Animations
  - بررسی frame به frame
  - تست drag روی گوشی واقعی (iOS Safari و Android Chrome)
  - نگاه دوباره در روز بعد

## چک‌لیست بازبینی هر کامپوننت UI

طبق `emil-design-eng`، این چک‌لیست برای هر کامپوننت دارای حرکت اجرا و نتیجه‌اش در گزارش تسک به شکل جدول Before/After/Why ثبت می‌شود.

| بررسی | معیار |
|---|---|
| `transition: all` | ویژگی‌ها دقیق نام برده شوند |
| ورود از `scale(0)` | از `scale(0.96)` و `opacity: 0` |
| `ease-in` | `--ease-out` یا curve مناسب از توکن‌ها |
| مبدأ popover | از trigger (Dialog مستثناست) |
| انیمیشن روی کار صفحه‌کلید | حذف |
| مدت بیش از 300ms | فقط sheet، Drawer، Dialog و toast |
| hover بدون media query | `(hover: hover) and (pointer: fine)` |
| keyframes روی عنصر پرتکرار | transition |
| مدت ورود و خروج برابر | خروج سریع‌تر |
| ظاهر شدن هم‌زمان همه | stagger کاهشی، حداکثر 6 کارت |
| reduced motion | fade ملایم، نه حذف کامل و نه حرکت مکانی |
| جهت RTL | مطابق جدول RTL؛ بدون left/right ثابت |
| مقدار خارج از توکن | ممنوع |

## پیشنهادهای هویت بصری (frontend-design، تأییدنشده)

توکن‌های [UX](04-UX-DESIGN.md) و تصویر مرجع نقطهٔ شروع‌اند. نسبت کنتراست اندازه‌گیری‌شده (WCAG 2.x):

| ترکیب | نسبت | نتیجه |
|---|---|---|
| text روی background | 14.75 | AA و AAA |
| muted روی background / surface | 5.07 / 5.57 | AA متن عادی |
| primary روی background | 7.49 | AA |
| سفید روی primary (دکمه) | 8.22 | AA |
| urgent روی background / surface | 5.66 / 6.21 | AA |
| border روی background / surface | 1.27 / 1.39 | فقط برای جداکنندهٔ تزئینی |

پیشنهادها:

1. **توکن `border-strong` برابر `#858B83`:** برای حاشیهٔ Input و کنترل‌ها با نسبت 3.49 روی surface و 3.18 روی background (حداقل 3:1 طبق WCAG 1.4.11). `border` فعلی فقط برای جداکننده بماند.
2. **حفظ خانوادهٔ رنگ:** ترکیب «زمینهٔ کرم گرم و لهجهٔ سفالی» از الگوهای رایج و قالبی طراحی‌های امروز است. چون تصویر مرجع و D08 این خانواده را تعیین کرده‌اند، تغییرش را پیشنهاد نمی‌کنم. تمایز CatBuzz از سبز جنگلی به‌عنوان رنگ اصلی و از حرکت «Buzz» پنجه می‌آید. سفالی فقط برای فوری می‌ماند و هرگز تزئینی استفاده نمی‌شود.
3. **ارقام:** ارقام فارسی با `font-variant-numeric: tabular-nums` در جدول‌های مالی و زمان‌ها، تا اعداد هنگام به‌روزرسانی جابه‌جا نشوند.
4. **تصویر مرجع:** تصویر صفحهٔ اول با نام CatBuzz بازتولید شود. لوگوی فعلی آن نام قدیمی است.
