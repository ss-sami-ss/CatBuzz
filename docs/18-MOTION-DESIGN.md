# طراحی حرکت (Motion Design)

نسخهٔ 1.1 (پیش‌نویس برای تأیید کارفرما) — 2026-11-15 — D20. این سند مرجع همهٔ انیمیشن‌های CatBuzz است. مقادیر از این اسکیل‌ها گرفته شده‌اند:

- `emil-design-eng` و `animate`: تصمیم انیمیشن، easing، مدت و spring
- `choreograph`: ترتیب و هم‌پوشانی چند عنصر
- `gestures`: کشیدن با انگشت
- `pick-ui-library`: انتخاب کتابخانه
- `vercel-react-best-practices`: کارایی
- `frontend-design`: هویت بصری

هنوز کدی ساخته یا تست نشده است. اجرای واقعی پس از تأیید کارفرما در T02، T04 و تسک‌های UI انجام می‌شود.

## شعار و معنای عملی

**سریع، معنادار، صیقل‌خورده.**

- **سریع:** انیمیشن UI زیر 300ms است. استثناها (sheet، Drawer، Dialog، toast و جشن) در جدول توکن‌ها آمده‌اند. خروج همیشه از ورود سریع‌تر است.
- **معنادار:** هر انیمیشن یکی از این هدف‌ها را دارد: بازخورد، پیوستگی مکانی، نمایش تغییر وضعیت، جلب توجه به فوریت یا جلوگیری از پرش ناگهانی. «قشنگ است» دلیل کافی نیست.
- **صیقل‌خورده:** فقط `transform` و `opacity` انیمیت می‌شوند. curveها سفارشی‌اند، هیچ چیز از `scale(0)` ظاهر نمی‌شود و حرکت قابل قطع است.
- **بازیگوشی:** فقط برای سه موفقیت: نجات گربه، تکمیل کمک مالی و تحویل به سرپرست دائم.

## دروازهٔ تصمیم: انیمیشن داشته باشد یا نه؟

پیش از ساختن هر انیمیشن، این دو سؤال به ترتیب پاسخ داده می‌شوند. اگر پاسخ منفی بود، کدی نوشته نمی‌شود و این یک نتیجهٔ درست است.

| دفعات دیدن | تصمیم | نمونه در CatBuzz |
|---|---|---|
| صدها بار در روز یا میان‌بر صفحه‌کلید | **بدون انیمیشن** | میان‌برها، بستن با Escape، جابه‌جایی focus، تایپ در جست‌وجو |
| ده‌ها بار در روز | بسیار کوتاه یا هیچ | hover کارت، chip فیلتر، تب‌های نوار پایین، انتخاب marker |
| گاه‌به‌گاه | انیمیشن استاندارد | sheet، Drawer، Dialog، toast، جابه‌جایی صفحه، نتایج تازه، پذیرش مأموریت |
| نادر | مجاز به بازیگوشی | نجات گربه، تکمیل کمک مالی، تحویل به سرپرست دائم |

داده‌ای که کاربر می‌خواند یا بر اساس آن تصمیم می‌گیرد برای زیبایی حرکت نمی‌کند. مبلغ و فاکتور count-up نمی‌شوند و نقشه تکان نمی‌خورد.

## Motion tokens

- **CSS:** توکن‌ها یک بار به شکل CSS custom property در `src/components/motion/tokens.css` روی `:root` تعریف می‌شوند.
- **JS:** springها و مقادیری که JS لازم دارد در `src/components/motion/tokens.ts` می‌آیند. یک تست واحد برابری مقادیر مشترک دو فایل را کنترل می‌کند.
- **مقدار تازه:** مقدار خارج از این جدول hard-code نمی‌شود. اگر مقدار تازه‌ای لازم شد، اول به همین سند اضافه می‌شود.

### مدت‌زمان

| Token | مقدار | کاربرد |
|---|---|---|
| `--duration-instant` | 0ms | کار صفحه‌کلید؛ حرکت مکانی در reduced motion |
| `--duration-press` | 140ms | بازخورد فشردن |
| `--duration-fast` | 160ms | tooltip، تغییر رنگ، خروج صفحه، fade حالت‌ها |
| `--duration-base` | 220ms | dropdown، ورود صفحه، تب، marker |
| `--duration-item` | 200ms | ورود هر کارت در stagger |
| `--duration-modal-in` / `--duration-modal-out` | 250 / 200ms | Dialog دسکتاپ |
| `--duration-shared` | 300ms | shared element (کارت به پرونده) |
| `--duration-progress` | 400ms | تغییر زندهٔ نوار پیشرفت کمک مالی |
| `--duration-drawer-in` / `--duration-drawer-out` | 450 / 300ms | Drawer و sheet بدون کشیدن |
| `--duration-toast` | 400ms | toast (با `ease`، طبق الگوی Sonner) |
| `--duration-pulse` | 1400ms × 3 بار | پالس حالت فوری |
| `--duration-celebrate` | 700ms | جشن موفقیت |
| `--stagger-delays` | 0، 35، 65، 90، 110، 125ms | تأخیر کارت‌های 1 تا 6 (فاصلهٔ کاهشی) |
| `--skeleton-delay` / `--skeleton-min` | 200 / 400ms | دیرتر نمایش دادن skeleton و حداقل مدت نمایش آن |

### Easing

| Token | مقدار | کاربرد |
|---|---|---|
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | ورود و خروج؛ پیش‌فرض |
| `--ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | حرکت و morph روی صفحه: shared element و نشانگر تب |
| `--ease-drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | Drawer و sheet |
| `ease` | استاندارد CSS | hover، تغییر رنگ، toast |
| `linear` | استاندارد CSS | نگه‌داشتن برای تأیید و چرخش spinner |

`ease-in` در UI ممنوع است.

### Spring (قالب Apple، با Motion)

| Token (TS) | مقدار | کاربرد |
|---|---|---|
| `spring.snap` | `{ type: "spring", duration: 0.4, bounce: 0 }` | رسیدن sheet یا Drawer به حالت بعدی پس از رها کردن آرام |
| `spring.release` | `{ type: "spring", duration: 0.45, bounce: 0.15 }` | رها کردن با flick یا drag-to-dismiss، با سرعت اولیهٔ انگشت |
| `spring.playful` | `{ type: "spring", duration: 0.5, bounce: 0.3 }` | فقط جشن موفقیت |

bounce فقط وقتی هست که انگشت «نیرو» داده است. همان sheet اگر با دکمه بسته شود bounce ندارد.

## قواعد کلی

1. **ویژگی‌ها:** فقط `transform` و `opacity` انیمیت می‌شوند. `width`، `height`، `top`، `left`، `margin`، `padding`، `background-position`، `clip-path` و `stroke-dashoffset` ممنوع‌اند. نوار پیشرفت با `scaleX` و shimmer با `translateX` ساخته می‌شوند.
2. **ورود:** هیچ چیز از `scale(0)` ظاهر نمی‌شود. شروع از `scale(0.96)` و `opacity: 0` است. برای عنصرهای کوچک تا `scale(0.9)` مجاز است.
3. **مبدأ:** popover، dropdown و tooltip از سمت trigger باز می‌شوند. Dialog مرکزی از مرکز باز می‌شود.
4. **قطع‌پذیری:** برای عنصر پرتکرار transition استفاده می‌شود، نه keyframes. هر چیزی که gesture به آن دست می‌زند spring یا transition دارد و هرگز keyframe ندارد.
5. **مسیر خروج:** خروج از همان مسیر ورود است، هم‌زمان و کوتاه‌تر. خروج stagger معکوس ندارد.
6. **فشردن:** هر عنصر قابل فشردن هنگام `:active` به `scale(0.97)` می‌رود (`--duration-press`، `--ease-out`).
7. **hover:** فقط داخل `@media (hover: hover) and (pointer: fine)`.
8. **reduced motion:** با `prefers-reduced-motion: reduce` حرکت مکانی، تأخیر stagger، پالس و جشن حذف می‌شوند، ولی fade کوتاه (`--duration-fast`) می‌ماند. کشیدن با انگشت یک‌به‌یک می‌ماند، چون کاربر خودش حرکت را می‌سازد. این قاعده همراه خود انیمیشن ساخته می‌شود، نه بعداً.
9. **یک ورود در هر ظرف** (`choreograph`): اگر ظرفی وارد می‌شود (صفحه، sheet یا Drawer)، محتوایش از قبل همان‌جاست و stagger جداگانه نمی‌گیرد.
10. **حلقهٔ بی‌پایان:** حلقهٔ بی‌پایان ممنوع است. پالس فوری فقط 3 بار اجرا می‌شود و کمتر از 5 ثانیه طول می‌کشد (WCAG 2.2.2). skeleton تنها استثنای تکرار است، چون با رسیدن داده متوقف می‌شود.
11. **ابزار:** ارزان‌ترین ابزاری که کار می‌کند انتخاب می‌شود (بخش «کتابخانه» را ببینید).

## دسترس‌پذیری: انیمیشن مانع نمی‌شود

- **صفحه‌کلید:** میان‌برها و Escape بی‌انیمیشن یا با `--duration-fast` اجرا می‌شوند. فعال کردن لینک یا دکمه با Enter یا Space مثل کلیک رفتار می‌کند. هیچ ورودی صفحه‌کلید تا پایان انیمیشن معطل نمی‌ماند.
- **focus:** با باز شدن sheet یا Dialog، focus فوراً به داخل آن می‌رود (نه پس از پایان انیمیشن) و با بستن، به trigger برمی‌گردد. پس از جابه‌جایی صفحه، focus روی عنوان `h1` صفحهٔ جدید قرار می‌گیرد. حلقهٔ focus مدیریت می‌شود و بیرون sheet با `inert` غیرفعال است.
- **صفحه‌خوان:**
  - DOM بلافاصله به‌روز می‌شود و انیمیشن فقط لایهٔ دیداری است.
  - عنصرهای تزئینی (پالس، ذرات جشن، shimmer) `aria-hidden` هستند.
  - وضعیت با متن اعلام می‌شود: «فوری» روی marker، `aria-busy` روی دکمهٔ در حال ارسال، و پیام موفقیت یا خطا در `aria-live` (خطا با `role="alert"`).
- **تعامل:** stagger، جشن و پالس `pointer-events` را نمی‌گیرند. View Transition در مدت کوتاه خود (≤300ms) کلیک را به لایهٔ انیمیشن می‌دهد، پس مدت آن از 300ms بیشتر نمی‌شود.
- **فرم‌ها:** پیام خطا کنار فیلد و با `aria-describedby` بدون انیمیشن مکانی ظاهر می‌شود. لرزش (shake) برای خطا استفاده نمی‌شود.

## جهت حرکت در RTL

جهت‌ها با «آغاز» (inline-start، در RTL سمت راست) و «پایان» (inline-end، در RTL سمت چپ) تعریف می‌شوند.

| حرکت | جهت در RTL |
|---|---|
| رفتن به صفحهٔ عمیق‌تر | صفحهٔ جدید از پایان (چپ) وارد می‌شود و صفحهٔ قبلی کمی به آغاز (راست) می‌رود |
| بازگشت | صفحهٔ فعلی به پایان (چپ) می‌رود و قبلی از آغاز (راست) برمی‌گردد |
| Drawer ناوبری | از آغاز (راست)، سمت sidebar دسکتاپ |
| Drawer فیلتر و جزئیات | از پایان (چپ) |
| bottom sheet و toast | عمودی؛ تحت تأثیر RTL نیست |
| swipe برای بستن toast یا کارت | به سمت پایان (چپ) |
| نوار پیشرفت کمک مالی | از راست به چپ: `transform-origin: right` و `scaleX` |
| ذرات جشن | از نقطهٔ تعامل به بیرون؛ بدون جهت ثابت |
| آیکون‌های جهت‌دار (بازگشت، chevron) | قرینه؛ آیکون پنجه و تیک قرینه نمی‌شوند |

`--dir` روی `:root` یک بار تعریف می‌شود: `1` برای LTR و `-1` برای RTL. «از پایان» با `translateX(calc(100% * var(--dir)))` نوشته می‌شود. متغیر CSS هرگز در حین انیمیشن یا drag تغییر نمی‌کند. مقدار drag مستقیم روی `transform` همان عنصر نوشته می‌شود.

## جاهایی که انیمیشن دارند

### ۱. جابه‌جایی بین صفحه‌ها

دفعات: گاه‌به‌گاه تا ده‌ها بار در روز. هدف: پیوستگی مکانی.

- **ناوبری سلسله‌مراتبی:** صفحهٔ جدید با `opacity` 0 به 1 و جابه‌جایی 24px از پایان در `--duration-base` و `--ease-out` وارد می‌شود. صفحهٔ قبلی در `--duration-fast` محو می‌شود.
- **ناوبری هم‌سطح** (تب‌های نوار پایین و sidebar): فقط crossfade در `--duration-fast`.
- **نقشه:** هرگز در transition صفحه حرکت نمی‌کند و state آن حفظ می‌شود.
- **بازگشت با gesture مرورگر:** وقتی مرورگر خودش انیمیشن بازگشت دارد (swipe در iOS Safari)، transition ما اجرا نمی‌شود.
- **ابزار:** React `<ViewTransition>` و `addTransitionType` برای جهت رفت و برگشت.
- **reduced motion:** crossfade کوتاه.

### ۲. تبدیل کارت گربه به صفحهٔ پرونده (shared element)

دفعات: گاه‌به‌گاه. هدف: پیوستگی مکانی (همین گربه است که بزرگ شد).

| عنصر | نقش | شروع | مدت | حرکت | رابطه |
|---|---|---|---|---|---|
| عکس گربه | Lead | 0ms | `--duration-shared` | morph جای و اندازه با `--ease-in-out` | — |
| نام گربه | Support | 0ms | `--duration-shared` | morph همراه عکس | با عکس، هم‌زمان |
| بقیهٔ صفحهٔ پرونده | Support | 60ms | `--duration-base` | fade و جابه‌جایی 8px | هم‌پوشان با عکس |
| کارت‌های دیگر فهرست | Static | — | — | fade خروج هم‌زمان | — |

- **پیاده‌سازی:** `<ViewTransition name={catTransitionName(catId)}>` روی عکس کارت و عکس سرصفحهٔ پرونده قرار می‌گیرد. در هر لحظه فقط یک عنصر با هر نام رندر می‌شود، که در فهرست مجازی‌شده لازم است.
- **محدودهٔ اجرا:** فقط هنگام رفتن از فهرست، bottom sheet یا marker به پرونده و بازگشت. لینک مستقیم یا refresh انیمیشن ندارد.
- **حریم خصوصی:** نام transition فقط شامل شناسهٔ عمومی گربه است.
- **reduced motion:** crossfade.

### ۳. bottom sheet، Drawer و Dialog

- **bottom sheet موبایل** (صفحهٔ اول، خلاصهٔ گربه، فیلترها): سه حالت بسته، خلاصه و باز (snap point).
  - **کشیدن (track):** sheet یک‌به‌یک همراه انگشت است، بدون easing یا spring.
  - **رها کردن (release):** مقصد از فاصله (بیش از 40% مسیر) یا سرعت (بیشتر از 0.11px/ms) تعیین می‌شود. حرکت با `spring.release` و سرعت اولیهٔ انگشت است، و برای بازگشت کوتاه با `spring.snap`.
  - **مرزها:** کشیدن بیش از حالت باز اصطکاک فزاینده دارد (rubber-band، حدود 0.2).
  - **کنترل لمس:** pointer capture فعال است، انگشت دوم نادیده گرفته می‌شود و `touch-action` روی محور کشیدن تنظیم می‌شود. drag فقط وقتی شروع می‌شود که محتوای داخلی در بالاترین نقطه باشد. دکمه‌های داخل sheet drag را شروع نمی‌کنند.
  - **پس‌زمینه:** در حالت خلاصه پس‌زمینه تیره نمی‌شود تا نقشه قابل استفاده بماند. در حالت باز، opacity پس‌زمینه از همان مقدار drag مشتق می‌شود (یک منبع حقیقت).
  - **باز و بسته با دکمه:** `--duration-drawer-in/out` و `--ease-drawer`، بدون bounce.
- **Drawer:** ناوبری از آغاز و فیلتر/جزئیات از پایان. کشیدن افقی برای بستن با همان قواعد.
- **Dialog:**
  - **دسکتاپ:** مرکزی، `scale(0.96)` و `opacity` در `--duration-modal-in/out` با `--ease-out`، از مرکز. پس‌زمینه هم‌زمان fade می‌شود.
  - **موبایل:** Dialog به شکل bottom sheet کشیدنی با spring نمایش داده می‌شود.
  - **پیشنهاد:** کشیدن و spring برای Dialog مرکزی دسکتاپ پیشنهاد نمی‌شود، چون به trigger وابسته نیست و gesture روی آن معنای مکانی ندارد.
  - **فرم پرشده یا تصمیم حساس** (رضایت مشاوره، پرداخت، فرم درخواست نگهداری با تغییر ذخیره‌نشده): drag-to-dismiss با مقاومت برمی‌گردد و تأیید بستن می‌خواهد.

### ۴. ظاهر شدن پشت‌سرهم کارت‌ها (stagger)

دفعات: گاه‌به‌گاه. هدف: نشان دادن «نتیجهٔ تازه».

| عنصر | نقش | شروع | مدت | حرکت |
|---|---|---|---|---|
| کارت 1 | Lead | 0ms | `--duration-item` | fade و بالا آمدن 10px |
| کارت‌های 2 تا 6 | Support | 35، 65، 90، 110، 125ms | `--duration-item` | fade و بالا آمدن 6px |
| کارت 7 به بعد | Support | 125ms | `--duration-item` | با کارت 6 |
| عنوان فهرست و شمارنده | Static | — | — | — |

- **مدت کل:** حدود 325ms است.
- **چه زمانی:** فقط وقتی نتیجه داخل همان صفحه تازه می‌شود («جست‌وجو در این محدوده» یا فیلتر). وقتی فهرست بخشی از ورود صفحه یا sheet است، ظرف آن را حمل می‌کند و stagger ندارد. صفحه‌بندی و refetch پس‌زمینه فقط fade کوتاه دارند.
- **ابزار:** CSS animation با `animation-fill-mode: both` و `--i` برای هر کارت. بدون JS.

### ۵. میکرواینترکشن‌ها

- **دکمه:**
  - فشردن با `scale(0.97)` است.
  - در حالت ارسال، برچسب در `--duration-fast` به spinner تبدیل می‌شود (crossfade با opacity). عرض دکمه ثابت می‌ماند تا layout نپرد.
  - `aria-busy` و `disabled` فعال می‌شوند. چرخش spinner با `rotate` و `linear` است.
- **پذیرش مأموریت** (MVI: `AcceptMission` ← pending ← نتیجهٔ سرور):
  - **موفقیت:** موفقیت فقط پس از پاسخ واقعی سرور نمایش داده می‌شود (هیچ موفقیت خوش‌بینانه یا جعلی). spinner به تیک تبدیل می‌شود (`scale(0.8)` به 1 و opacity، `--duration-base`). وضعیت کارت مأموریت crossfade می‌شود و پیام «مأموریت را پذیرفتید» در `aria-live` اعلام می‌شود.
  - **خطا (مثل `MISSION_FULL`):** دکمه به حالت قابل اقدام برمی‌گردد و پیام خطا با fade و `role="alert"` نمایش داده می‌شود. حرکت مکانی ندارد.
- **نوار پیشرفت کمک مالی:**
  - در بار اول مقدار نهایی بدون انیمیشن نمایش داده می‌شود، چون داده است، نه نمایش.
  - فقط وقتی مبلغ تأییدشدهٔ سرور در همان صفحه تغییر کند، نوار با `scaleX` از مقدار قبلی به جدید در `--duration-progress` و `--ease-out` از راست به چپ پیش می‌رود.
  - عدد مبلغ انیمیت نمی‌شود. رسیدن به 100% جشن «تکمیل کمک مالی» را اجرا می‌کند.

### ۶. markerهای نقشه و حالت فوری

- **ظاهر شدن:** markerهای نتیجهٔ تازه با `scale(0.9)` و opacity در `--duration-base` ظاهر می‌شوند. چون تعدادشان زیاد است و پرتکرارند، stagger ندارند.
- **انتخاب:** marker انتخاب‌شده به `scale(1.12)` با `--duration-press` می‌رود و کارت همگام فقط تغییر رنگ دارد. pan، zoom و cluster با انیمیشن خود کتابخانهٔ نقشه انجام می‌شوند.
- **پالس فوری:** یک حلقهٔ تزئینی پشت marker فوری (`::before`، `aria-hidden`) از `scale(1)` و `opacity: 0.5` به `scale(1.8)` و `opacity: 0` در `--duration-pulse` با `--ease-out` می‌رود.
  - **دفعات:** فقط 3 بار، هنگام اولین نمایش یا وقتی فوریت تازه ثبت شود. بعد حلقهٔ ثابت می‌ماند.
  - **وضعیت متنی:** خود marker برچسب متنی «فوری» دارد، چون رنگ و حرکت تنها حامل وضعیت نیستند (N02).
  - **reduced motion:** فقط حلقهٔ ثابت.
- **وابستگی به D07:** اگر کتابخانهٔ نقشه markerها را با WebGL رسم کند، پالس با لایهٔ همان کتابخانه و همین مشخصات ساخته می‌شود.

### ۷. Skeleton و حالت‌های خالی، موفقیت و خطا

- **Skeleton:**
  - فقط اگر بارگذاری بیش از `--skeleton-delay` طول بکشد نمایش داده می‌شود. وقتی نمایش داده شد، حداقل `--skeleton-min` می‌ماند تا چشمک نزند.
  - shimmer با `translateX` یک لایهٔ گرادیان است و در reduced motion ثابت می‌شود.
  - شکل skeleton با layout واقعی یکی است تا هنگام رسیدن داده layout نپرد.
  - تبدیل به محتوا با crossfade در `--duration-fast` است و stagger جدا ندارد.
- **خالی:** fade در `--duration-base` با تصویر ثابت پنجه و یک اقدام روشن (مثل «ثبت اولین گزارش»). حرکت تزئینی ندارد.
- **موفقیت معمولی:** toast با Sonner (از پایین، `--duration-toast`، swipe به پایان). جشن فقط برای سه موفقیت بخش بعد است.
- **خطا:** fade بدون حرکت مکانی. focus به خلاصهٔ خطا می‌رود و `role="alert"` دارد. نوار آفلاین با `translateY(-100%)` به 0 در `--duration-base` وارد می‌شود.

### ۸. لحظه‌های بازیگوش و جشن

فقط این سه موفقیت جشن دارند و فقط پس از ثبت قطعی در سرور:

| موفقیت | رخداد سرور |
|---|---|
| نجات گربه | مأموریت امداد یا انتقال با نتیجهٔ «نجات یافت» تکمیل و تأیید شد |
| تکمیل کمک مالی | درخواست حمایت با پرداخت‌های تأییدشده به `funded` رسید |
| تحویل به سرپرست دائم | handover placement دائم با تأیید هر دو طرف ثبت شد |

| عنصر | نقش | شروع | مدت | حرکت |
|---|---|---|---|---|
| آیکون پنجه (لرزش «Buzz») | Lead | 0ms | `--duration-celebrate` | چرخش 8- به 8+ درجه و بازگشت با `spring.playful` |
| 6 تا 8 ذرهٔ پنجه | Decoration | 0 تا 40ms | ≤ 600ms | از نقطهٔ تعامل به بیرون با `translate` و `scale(0.9)` و محو شدن در 20% آخر |
| متن موفقیت | Support | 0ms | `--duration-base` | fade؛ اعلام در `aria-live` |

- **دفعات:** یک بار برای هر رخداد و کاربر. بازدید دوباره یا refresh جشن را تکرار نمی‌کند.
- **مخاطب:** فقط برای کاربرانی که در همان لحظه درگیر رخدادند. در feed دیگران جشن نداریم.
- **محدودیت‌ها:** confetti تمام‌صفحه، صدا، قفل صفحه و دزدیدن focus نداریم. ذرات `aria-hidden` و `pointer-events: none` دارند.
- **پیاده‌سازی:** حرکت روی `div` دور SVG اعمال می‌شود، نه خود SVG.
- **reduced motion:** فقط تیک ثابت و متن.

## ساختار `src/components/motion`

بر اساس AGENTS («abstraction بدون مصرف واقعی نسازید»)، هر جزء وقتی ساخته می‌شود که اولین مصرف‌کنندهٔ واقعی‌اش آماده باشد. صفحهٔ نمونهٔ مرحلهٔ ۵ مصرف‌کنندهٔ اول این اجزاست.

```text
src/components/motion/
  tokens.css               CSS custom properties، --dir، media queryهای reduced motion
  tokens.ts                durationها و springهای JS (تست برابری با tokens.css)
  use-reduced-motion.ts    سازگار با SSR؛ پیش‌فرض امن تا hydration
  use-delayed-visibility.ts  منطق skeleton-delay / skeleton-min (تابع خالص و تست‌پذیر)
  stagger.tsx              Stagger / StaggerItem مبتنی بر CSS؛ سقف 6
  page-transition.tsx      wrapper روی ViewTransition؛ جهت با addTransitionType
  shared-element.tsx       catTransitionName و wrapper نام‌دار
  sheet.tsx                Base UI Drawer با snap point و توکن‌ها
  dialog.tsx               Base UI Dialog؛ زیر 768px به sheet تبدیل می‌شود
  progress-bar.tsx         scaleX، RTL، انیمیشن فقط روی تغییر زنده
  pulse-ring.tsx           پالس سه‌باره، aria-hidden
  skeleton.tsx             shimmer با translateX
  celebration.tsx          بارگذاری تنبل Motion؛ یک بار برای هر رخداد
```

- **MVI:** باز یا بسته بودن sheet، حالت فعلی و pending در Model است. مقدار لحظه‌ای drag در motion value یا ref است، نه React state.
- **منطق خالص:** انتخاب snap point از فاصله و سرعت، و منطق skeleton تابع خالص با تست واحدند.

## کارایی (vercel-react-best-practices)

- **CSS برای حرکت از پیش تعیین‌شده:** Motion فقط در کامپوننت‌های sheet، Dialog و جشن است، با import مستقیم (`bundle-barrel-imports`)، `next/dynamic` و preload روی hover/focus (`bundle-dynamic-imports`، `bundle-preload`). `LazyMotion` در T02 روی نسخهٔ قفل‌شده سنجیده می‌شود.
- **بدون re-render در هر frame:** مقدار drag در motion value یا ref است (`rerender-use-ref-transient-values`). listenerهای touch و scroll passive هستند.
- **فهرست بلند:** `content-visibility: auto`. layout animation در Motion (`layout`، `layoutId`) روی main thread است و بدون دلیل اندازه‌گیری‌شده استفاده نمی‌شود.
- **SSR:** انیمیشن ورود نباید hydration mismatch یا پرش بسازد. محتوای SSR بدون انیمیشن دیده می‌شود.
- **هدف:** INP ≤ 200ms (N03) با انیمیشن‌ها روی دستگاه میان‌رده اندازه‌گیری می‌شود.

## آزمون

- **e2e:** Playwright با `reducedMotion: 'reduce'` برای پایداری اجرا می‌شود. یک مسیر هم با حرکت کامل برای sheet، Dialog و shared element تست می‌شود: focus، Escape، بازگشت focus، اعلام `aria-live` و نبود اسکرول افقی در 360px (Q28).
- **unit:** انتخاب snap point، `use-delayed-visibility`، دفعات پالس و یک‌باره بودن جشن تست واحد دارند. یک تست هم برابری `tokens.ts` و `tokens.css` را کنترل می‌کند.
- **feel-check دستی** (ثبت در گزارش تسک):
  - پخش 2 تا 5 برابر کندتر و بررسی frame به frame
  - تست drag روی iOS Safari و Android Chrome واقعی
  - تست صفحه‌خوان (NVDA یا VoiceOver)
  - نگاه دوباره در روز بعد
